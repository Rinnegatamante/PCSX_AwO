# Standalone Z80

`libpcsxcore/arcade/z80.cpp/.h` adapts the actual MAME NMOS Z80 engine from `src/devices/cpu/z80` at commit `deb2f54fe7300e7a192690318beb860159bfd52a`. Upstream credits Juergen Buchmueller and Andrei I. Holub; `z80make.py` spells its generator credit Andre I. Holub. Sources are BSD-3-Clause; see `z80_LICENSE.txt`.

This is a CPU component for board adapters such as Capcom ZN, Taito FX, and Zoom. This change supplies no board ROMs, banking responses, sound chips, media, or board-boot claim.

## Actual instruction engine and dependencies

The component retains all 256 entries in each of the base, CB, ED, DD, and FD tables, plus the shared 256-entry indexed-CB table used by DDCB and FDCB. All seven external instruction families are exercised in tests, 1,792 dispatches. The bodies include 8/16-bit operations, alternate registers, stack/branches, IX/IY half registers, undocumented shifts/register copies, bit operations, I/R/refresh, repeating block transfers/compares/I/O, HALT, interrupt modes, EI delay, and RETI/RETN.

MAME's current Z80 uses a resumable bus-cycle engine generated by `z80make.py` from `z80.lst`. The standalone generator imports that primary source expander, adapts IRQ-vector sourcing, retains its bus-cycle expressions and resume states, and adds instruction-completion accounting/debugger-step hooks. It does not replace opcode bodies with a subset or fabricate operations. The original list and generator are retained as `z80_mame.lst` and `z80_mame_make.py`; generated C++ is `z80_execution.inc`, with helper algorithms in `z80_helpers.inc`.

MAME address spaces are replaced by byte callbacks; devcb pin/refresh/no-request outputs are optional callbacks. Daisy-chain IRQ selection and RETI notification are caller hooks. Host scheduler, debugger, save-state, device factory, and disassembler dependencies are removed. The only compiled translation unit is `z80.cpp`, requiring C++17 for the upstream generated `[[fallthrough]]`/`[[maybe_unused]]` constructs. The public header compiles as C99.

## API and bus behavior

`z80_create(&config)` creates an opaque CPU; `z80_destroy` releases it. The config contains:

- Memory read/write callbacks with 16-bit addresses.
- An optional separate M1/opcode-read callback, suitable for a board that supplies decrypted opcodes. Instruction operands still use ordinary memory reads.
- I/O read/write callbacks with the full 16-bit port address. Immediate IN/OUT use A as the high byte; `(C)` instructions use BC, including the real block-I/O update ordering.
- IRQ vector acknowledgement, optional RETI notification, and optional HALT/BUSACK/IRQACK notification, refresh-address, no-memory-request-address, and diagnostic callbacks.

Unconfigured memory/opcode/I/O reads return 0xff. Unconfigured writes have no recipient. Those are bus defaults, not supplied program or device responses.

`z80_irq` controls the level-sensitive maskable interrupt. `z80_nmi` latches a rising edge, matching upstream's suppression of the edge before the first clock has elapsed. `z80_wait` stalls execution at the next run invocation; `z80_busreq` is handled at an instruction/service boundary and changes BUSACK. WAIT/BUSREQ consume scheduler time while stalled. The IRQACK callback follows upstream's assertion notification; it is not a complete electrically timed acknowledge pulse model.

`z80_get_status` exposes main/alternate registers, I/R, interrupt/HALT/pin state, execution phase, T-state count, completed-instruction/IRQ/NMI counts, undocumented-opcode/unsupported-operation counts, and cycle debt. `get_register/set_register` use the `Z80_*` enums. F/AF setters update the engine's lazy flags correctly. Changing PC abandons the active execution phase and resets scheduler debt. Other register edits should be made at an instruction boundary. Status is introspection, not a complete restorable in-flight snapshot.

## Timing and scheduling

`z80_run_cycles(cpu, nominal_tstates)` executes the requested nominal oscillator T-state budget. Standard M1, memory, and I/O costs are 4, 3, and 4 T-states, with the upstream instruction-specific extra cycles. Unlike M37710, no divide-by-two conversion is applied to the caller's Z80 crystal-clock budget.

Execution can pause between bus-cycle steps. A memory/I/O step can overshoot a short budget; the adapter retains the resulting debt and pays it from later nominal budgets. Feed nominal budgets continuously and do not subtract the return value from the next budget. The return counts actual elapsed T-states for the invocation, and may exceed the request or be zero while paying earlier debt. The same total nominal budget in small and large slices produces the same register/execution-phase/cycle state.

Callbacks execute at the upstream bus-step point. `get_status().cycles` remains meaningful from inside a callback. The engine retains safe yielding for an arbitrarily long stream of DD/FD prefixes. There are no invented external wait states or board-specific clock conversions.

`z80_step_instruction` is a debugger/test convenience that completes one instruction, or one HALT fetch cycle. If an interrupt is accepted first, its entry time is included before the first handler instruction, as in the source service loop. It clears scheduler debt independently of nominal scheduling. WAIT/BUSREQ return zero; a pathological prefix stream is bounded at 65,536 T-states and can leave a resumable phase rather than hanging indefinitely.

## Interrupts and retained limitations

The engine implements EI's one-instruction delay, HALT release, NMI edge priority, stack pushes, IFF1/IFF2, IM1 RST 0x38, and IM2's actual byte-indexed vector fetch, including odd vectors and the 0xff boundary. RETI calls the optional caller daisy-chain hook; the component does not own a daisy-chain device graph.

Upstream IM0 supports NOP, EI, RST, and the MAME acknowledgement encoding `0xcdAAAA` for CALL or `0xc3AAAA` for JP. Arbitrary injected IM0 opcodes are an upstream TODO. Unsupported IM0 vectors emit `Z80_DIAG_IM0_UNSUPPORTED`, retain the source behavior, and increment a counter; they are not silently claimed fully emulated.

Undefined ED bytes act as the upstream undocumented NOPs. Ignored DD/FD prefixes execute the base opcode. Both increment the undocumented counter; they are not fatal CPU faults. The model retains NMOS undocumented flags, including Q-dependent SCF/CCF and indexed BIT X/Y behavior. MAME's `HAS_LDAIR_QUIRK` is zero, so its LD A,I/R interrupt parity glitch remains disabled. CMOS differences and Z80N/R800/eZ80/NSC800 derivatives are not enabled by this component.

Creation follows upstream initial register values, including IX/IY=0xffff and initial Z set. `z80_reset` follows upstream `device_reset`: it leaves HALT, clears PC/WZ/I/R/IFF and the pending NMI/EI-related service state, and resets the execution phase. Other general/alternate registers, the current IM latch, external line levels, and cumulative counters are retained, as in that source. This documents the imported implementation; tests do not establish every reset/undocumented edge against physical silicon.

## Verification and regeneration

```sh
make -f tests/Makefile.z80 test
make -f tests/Makefile.z80 BUILD=build/z80-sanitize \
  CXXFLAGS='-std=c++17 -O0 -g -Wall -Wextra -Werror -fsanitize=address,undefined -fno-omit-frame-pointer' test
```

The deterministic suite verifies 10,304 independently calculated byte arithmetic/flag/timing cases (binary ALU, INC/DEC, all DAA input combinations, all CB rotate/shift inputs), 864 independent 16-bit ADD/ADC/SBC cases, all 1,792 external opcode dispatches, exact representative instruction costs, DD/FD substitution and indexed-CB behavior, indexed BIT undocumented flags, LDIR/LDDR/CPIR and INIR/OTIR repeated timing, I/O ports, RRD/RLD, separate opcode-vs-operand reads, IM0/1/2/NMI/EI/RETI/RETN/HALT, and scheduler debt/WAIT/BUSREQ/prefix yielding.

The sanitizer recipe uses O0 because optimizing the large generated dispatch function with instrumentation is unusually expensive. The ordinary target uses O2. The opcode smoke sweep proves dispatch/execution coverage, not complete semantic correctness of every opcode. Fixed expected arithmetic vectors come from an independent Python width-limited reference, without importing or executing the port; the fixture records the upstream equation-source SHA-256. No arcade ROM run has been performed for this component.

Regenerate from the repository root:

```sh
python3 libpcsxcore/arcade/z80_generate.py ../mamedev/src/devices/cpu/z80
python3 tests/z80_vectors_generate.py
```
