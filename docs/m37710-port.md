# Standalone Mitsubishi M37702/M37710

`libpcsxcore/arcade/m37710.cpp` adapts MAME's instruction engine behind the C-compatible API in `m37710.h`. The upstream source is `src/devices/cpu/m37710` at MAME commit `deb2f54fe7300e7a192690318beb860159bfd52a`, under BSD-3-Clause, copyright R. Belmont and Karl Stenerud. The retained license is `m37710_LICENSE.txt`.

This is a CPU component. No System11 game or C76 BIOS was available for execution during this port, so there is no System11 boot claim. Tests use synthetic programs and a synthetic internal ROM.

## Instruction engine

All four upstream M/X modes are compiled, with all 256 base dispatch slots, 135 B-accumulator prefix slots, and 33 multiply/divide prefix slots per mode. There are 1,696 valid dispatch slots across the four modes. Undefined prefix combinations fault explicitly instead of silently continuing. The M37702/M37710 has no 6502 emulation mode; the `M37710_E` register always reads zero.

The source implements separate A and B accumulators, preserved high halves of A/B/X/Y in 8-bit modes, native stacks, direct-page/data/program banks, 24-bit addressing, subroutines, interrupts, block moves, immediate-to-memory LDM, bit operations, decimal arithmetic, and the 0x42/0x89 instruction prefixes. This is the full instruction implementation supplied by MAME for these CPU models; newer 7750 signed arithmetic extensions are outside its scope.

`m37710_generate.py` retains the source macros, inline helpers, class declarations, opcode definitions, vectors, and interrupt arbitration. The standalone adapter supplies the bus, register map, scheduler, and callbacks. One C++11 translation unit includes all four instruction modes; there is no MAME build dependency.

## API and clocks

Create a CPU with `m37710_create(&config)`, then use `m37710_run_cycles(cpu, budget)`, `m37710_irq(cpu, line, asserted)`, and `m37710_get_status(cpu, &status)`. Destroy with `m37710_destroy`. `m37710_reset` resets the CPU/peripheral control state while preserving RAM, supplied ROM, and cumulative diagnostic counters.

CPU cycles are crystal clocks divided by two, matching MAME's `execute_clocks_to_cycles`. Namco C76 uses a 16,934,400 Hz crystal, giving 8,467,200 CPU cycles per second. Its MAME wrapper is `src/mame/namco/namcomcu.cpp`, where C76 subclasses M37702M2.

Feed nominal CPU-cycle budgets every scheduler slice. Execution finishes whole instructions and keeps overshoot debt across calls. The returned value counts cycles actually executed or spent stopped during that call; it can exceed the budget or be zero while paying earlier debt. Do not subtract the return value from subsequent nominal budgets. WAI advances to scheduled peripheral events; eligible interrupts resume execution. STP and illegal-opcode faults require reset to resume.

`read8/write8` callbacks use logical 24-bit addresses. Optional `read16/write16` callbacks exchange aligned little-endian logical words atomically. Unaligned words fall back to two byte accesses, as do words when the optional callbacks are absent. Accesses touching internal memory or peripheral bytes go through the internal map, even when the neighboring byte is external. External callbacks are responsible for board ROM, shared RAM, C352, and other devices. A read without a configured external callback returns an undriven 0xff byte.

`m37710_read8/read16/write8/write16` expose the same bus path for a board adapter or debugger. `get_register/set_register` use the upstream `M37710_*` register enums; status includes full preserved registers, combined PS/IPL, actual cycles, instruction/IRQ counts, illegal/unsupported counters, and timer expiration counts. Debugger setters add program/data-bank and direct-page support and retain high index halves when setting an 8-bit index register.

## Models and required ROM

| Model | Internal RAM | Internal ROM | GPIO |
|---|---|---|---|
| M37702M2 / C76 | 0x000080–0x00027f, 512 bytes | 0x00c000–0x00ffff, 16 KiB | P0–P8 |
| M37702S1 | 0x000080–0x00027f, 512 bytes | External bus | P0–P8 |
| M37710S4 | 0x000080–0x00087f, 2 KiB | External bus | P4–P8 |

M37702M2 creation requires a caller-provided internal ROM of exactly 16,384 bytes. The adapter copies it and rejects missing/wrong-length ROMs. Other models reject a nonzero internal ROM length. Nothing generates a BIOS or authentication response. The reset vector is a little-endian word at 0x00fffe.

Ports use MAME's interleaved data/direction byte layout. Reads combine callback input bits with latched output bits according to the direction register. Writes call `port_write` with the driven value and direction mask. Missing input callbacks return zero, matching the upstream callback default. P9/P10 are absent on the three exposed models.

## Timers, ADC, and IRQs

Eight timers are mapped at 0x40/0x42/0x44 and 0x46–0x5d. Periodic timer mode schedules `(value + 1)` times CPU-cycle prescalers `{1, 8, 32, 256}`, corresponding to upstream crystal divisors `{2, 16, 64, 512}`. Expiration raises the actual Timer A0…A4/B0…B2 vector request. Reload periods are latched on count-start activation, as upstream; clearing count-start cancels the event. The upstream performance shortcut that drops value-zero, fastest-clock timers is intentionally omitted.

Event-counter mode changes the 16-bit counter on an asserted `m37710_timer_input` call. Timer A direction follows its up/down control or `m37710_timer_direction`; Timer B counts down. This is the upstream external-tick behavior. Overflow/reload/output effects in event-counter mode remain unimplemented upstream and here.

ADC control, sweep, and result registers are mapped at 0x1e–0x2f. Conversion takes 114 or 228 CPU cycles. Actual callback values are stored; single conversion, repeat, and sweep scheduling follow the upstream equations, including interrupt generation when conversion finishes. Long instructions process every elapsed ADC deadline. Missing analog callbacks supply zero rather than an invented board input.

Interrupt control registers are mapped at 0x70–0x7f. Arbitration follows MAME's priority and tie ordering: an unmasked request needs a priority above the CPU IPL; internal nonmaskable sources win. Entry pushes PG, PC, IPL, and PS, consumes 13 CPU cycles, clears the accepted request, sets I/IPL, and reads the vector from bank zero. RTI restores that stack. `irq_ack` reports the accepted source. The pin API uses `M37710_LINE_IRQ0/1/2`; callers must run the CPU between assertion and deassertion if they expect a short pulse to be serviced.

## Limits and adapter differences

Instruction costs come from MAME's existing timing macros. This is not a bus-cycle-accurate interpreter: external wait states, pin timing within an instruction, and hardware validation of every flag edge are absent. A long instruction completes before a newly scheduled interrupt can be taken. WAI/STP use scheduler time rather than a separately validated entry cost.

The adapter normalizes sequential PC overflow into PG at instruction boundaries. Relative branch helpers retain MAME's 16-bit PC wrapping within the current program bank. Upstream's introductory comment describes bank carry for relative branches, but its implementation/disassembler wrap the PC; cross-bank branch and operand/prefix boundary behavior remain unresolved rather than claimed hardware-verified. Reset reconstructs preserved high register halves before selecting 16-bit mode instead of retaining upstream's inconsistent split halves with M cleared.

UART mode, baud, and control latches retain upstream writable/read-only bit rules, but serial shift/transmit/receive behavior is absent. Transmit-buffer and receive-buffer accesses emit unsupported-peripheral diagnostics; they do not simulate successful communication. Watchdog timing, DMA, timer one-shot/PWM/pulse measurement, DAC/waveform/pulse outputs, and software-reset processor-mode side effects are not implemented. Unsupported implemented-register operations report `M37710_DIAG_PERIPHERAL`. Unmapped internal bytes follow MAME's `noprw` behavior and read zero. There is no in-flight state serialization API.

The source engine retains upstream arithmetic semantics, including unverified decimal and multiply/divide flag edges. Passing the binary reference vectors does not establish that every inherited MAME edge case matches silicon.

## Validation and regeneration

Run:

```sh
make -f tests/Makefile.m37710 test
make -f tests/Makefile.m37710 BUILD=build/m37710-sanitize \
  CXXFLAGS='-std=c++11 -O1 -g -Wall -Wextra -Werror -fsanitize=address,undefined -fno-omit-frame-pointer' test
```

The deterministic suite checks:

- Four width modes, separate A/B, and high-half preservation.
- 576 checked-in binary ALU and instruction-cost vectors calculated by an independent Python width-limited arithmetic reference.
- 224 A/B load/store traces across 14 addressing families and all four width modes.
- Execution of every valid source-derived opcode dispatch slot in all four modes, 1,696 cases. These are dispatch smoke tests, not semantic proofs for every instruction.
- Binary/BCD examples, multiply/divide, JSR/JSL/RTS/RTL, IRQ/WAI/RTI/IPL, zero division, and invalid-prefix diagnostics.
- Little-endian word callbacks, 24-bit data/program banks, internal ROM protection, RAM persistence, and all three memory profiles.
- GPIO masks, ADC deadlines/repeat under a long instruction, periodic timer start/reload/stop, event direction, timer-generated IRQ, and equivalence of small/large scheduler slices.

Regenerate the retained instruction source from the repository root:

```sh
python3 libpcsxcore/arcade/m37710_generate.py ../mamedev/src/devices/cpu/m37710
python3 tests/m37710_vectors_generate.py
```

The latter regenerates independent ALU fixtures and, when the neighboring MAME tree exists, the source-derived opcode smoke enumeration with its source SHA-256. Do not substitute synthetic ROM fixtures for real C76 media when integrating a board.
