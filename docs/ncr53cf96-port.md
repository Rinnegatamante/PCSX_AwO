# NCR53CF96-2 controller port

This standalone controller core is derived from MAME `src/devices/machine/ncr53c90.cpp` and `.h` at revision `deb2f54fe7300e7a192690318beb860159bfd52a`. The upstream files credit Olivier Galibert and carry BSD-3-Clause. MAME defines the 53CF96 as a subclass of its 53CF94 implementation and explicitly leaves CF96-specific fast-mode differences unimplemented; this module follows that current behavior.

The chip runs from a caller-supplied clock (16 MHz on Konami GV/GQ/Twinkle boards). It exposes the 16-register NCR aperture, 16-byte FIFO, 16/24-bit transfer counter, byte and 16-bit DMA methods, IRQ/DRQ callbacks, and an absolute chip-cycle scheduler for the controller's selection, REQ/ACK, reset, and transfer delays. A board maps the low byte lane over its 32-byte aperture and connects IRQ to the PSX IRQ input. MAME's SCSI endpoint default ID is 7; writing register 8 changes `m_scsi_id` as in upstream. Register 4 selects the target ID.

The NCR talks through callbacks at the NSCSI wire boundary. It drives SCSI control/data lines and requests line-change notifications; the caller supplies the other devices' wired-OR levels with `ncr53cf96_bus_changed` only when the resolver's `ctrl_wait` policy would notify this endpoint. The event records the external sample and runs controller sequencing without a synchronous callback from the bus resolver. This preserves the source's selection and phase handshakes. An absent target stays absent and selection times out through the controller state machine; the core never fabricates READY or a disc response.

Konami's current MAME wiring uses NCR ID 7, DMA channel 5, and IRQ `intin10` (PSX I_STAT bit 10). GV and Twinkle attach an XM5401 CD-ROM at SCSI ID 4; GQ attaches a hard disk at ID 0. Mounted CHD/raw target backends are outside this controller module. Until those target implementations and their media are available, it cannot claim to execute game disc I/O. The scripted target in unit tests only exercises line selection, command phase, status phase, and DMA transfer behavior; it is not available to runtime boards.

The NCR's initiator register, FIFO, transfer count, interrupt, byte-DMA, and phase engine are implemented. The MAME source's 16-bit DMA behavior and CF94 configuration registers are included. These Konami configurations use the CF94 default `BUSMD_0`; consequently the source's alternate-BUSMD `config3` DRQ thresholds do not apply here. `fifo_align_w` only stores its value in the pinned source; it is not used by the current DMA routines. The upstream source does not complete target-mode command execution: it accepts some target-mode commands in `check_valid_command` but has no corresponding `start_command` cases and reaches `fatalerror`. This port reports those commands as illegal-command interrupts instead of terminating the process. Arbitration loss also reaches `fatalerror` upstream; here it is recorded as a gross-error/illegal-command condition with `NCR53CF96_FAULT_ARBITRATION_LOST`, never as a clean disconnect.

The pinned source defines `DELAY_HACK`: after releasing BSY with no responding target, the active code waits `delay(1)` and then `delay(1000)` before disconnecting. The `8192 * select_timeout` alternative is compiled out. Register 5 still stores the timeout byte, but changing it does not change this MAME timing path. Chip reset leaves an already scheduled timer armed and doesn't release its data-bus drive; a full two-command queue rejects a following RESET/RESET BUS command before the reset-command priority check. CONFIG bit 3 sets a sticky test-mode latch until reset, while TEST writes only log a message in upstream. Tests preserve these source quirks. The core additionally rejects backward time and cycle deadlines that overflow `uint64_t` through explicit fault bits.

Run the focused tests with:

```sh
make -f tests/Makefile.ncr53cf96 test
```

The tests check register slots and the 32-byte low-lane adapter convention, 24-bit transfer-count registers, FIFO capacity/underflow, interrupt acknowledge, no-target arbitration timeout, scripted selection and phase changes, byte and word DMA including odd-byte count behavior, reset timer/data-line retention, test-mode latch, command queue reset ordering, external SCSI reset handling, and bounded cycle overflow/rewind. They verify deterministic chip-cycle deadlines without host wall-clock timing.
