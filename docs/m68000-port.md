# Standalone MAME MC68000 core

This adapter uses the MAME 68000 microcoded execution core at commit
`deb2f54fe7300e7a192690318beb860159bfd52a`. The processor handlers and decoder
are generated at build time from the retained upstream `m68000.lst` and
`m68000gen.py`; the engine does not hand-code a substitute instruction set.
The source notice and complete BSD-3-Clause terms are in
`libpcsxcore/arcade/m68000/LICENSE.txt`.

The build generates the direct, full-instruction and direct, partial-instruction
handler tables (`sdf` and `sdp`). MAME selects these for a normal MC68000 without
an MMU. The indirect (`sif`/`sip`) tables, MMU translations, and other 680x0
models are deliberately unsupported. This adapter uses the same 16-bit
big-endian program/opcode/cpu-space bus interface and 24-bit byte address range.
Bus callbacks receive the aligned word address and MAME's active-one lane mask
(`0xffff` is a full word; `0xff00` and `0x00ff` are upper and lower byte lanes).
The core handles reset vectors, supervisor/user stack selection, autovectors,
STOP, exception entry/RTE, partial instruction execution, and bus-error entry.
A failed read/write callback reports a bus error; the API's diagnostic flag
remains set until reset.

Call `run()` with any cycle budget, including one-cycle slices. The generated
handler's instruction and micro-operation state remains in the core across
calls, including when an instruction spans the budget boundary. `total_cycles`
counts requested budgets and starts at `M68000Bus::cycle_origin` (zero by
default). `run()` rejects a request that would overflow its 64-bit absolute
cycle counter before changing CPU or callback-visible state. It returns `-1`
for that overflow and `-2` when called synchronously from a bus or IRQ-ack
callback. Reset and IRQ-ack replacement are also rejected during callbacks;
the sticky `callback_fault()` diagnostic records any such attempt. `set_irq()`
and const inspection calls are callback-safe so an IRQ-ack callback can lower
its line. The object must not be destroyed, moved, or move-assigned from one
of its callbacks, because callback execution is synchronous and the outer run
owns the object state.

Host code supplies real bus contents and device callbacks; the core has no
guest BIOS, firmware patch, or synthesized bus data.
The default CPU-space map returns MAME's level-1 through level-7 autovector
bytes. Set `use_default_autovectors` false in `M68000Bus` to route CPU-space
cycles through a board's own callback.

Run synthetic vector/ALU/MMIO and cycle-slicing checks, arithmetic flags and
shift/MOVEM instructions, privilege and address errors, STOP/IRQ/RTE including
level-7 NMI, bus-error vectors/frames (including a one-shot failed critical
stack write), callback guards, and cycle-overflow checks with:

```sh
make -f tests/Makefile.m68000 CXX=clang++ test
make -f tests/Makefile.m68000 CXX=clang++ sanitize
```

These fixtures validate the standalone CPU adapter. They do not claim a board
integration or authentic game boot.
